## 公网连接与网站验收

验收客户端使用官方 darwin-arm64 v2.13.0，通过本机 SOCKS 接口发出代理请求。服务端地址分别指定为真实 IPv4 和 IPv6，SNI 为部署域名，未关闭证书验证。服务器日志分别记录到对应来源的认证连接，代理出口分别与 JP2 的 IPv4、IPv6 一致。临时客户端配置已删除，报告与 Git 仓库不保存真实密码、分享链接或私钥。

从另一台服务器（JP1）经 JP2 公网地址进行独立 HTTPS 对照：

- IPv4：21 / 21 文件与网站包的 SHA-256 一致。
- IPv6：21 / 21 文件与网站包的 SHA-256 一致。
- 首页、文章页及约 446 KB 图片的单独抽查均为 HTTP 200，耗时约 0.07–0.14 秒。
- 本地电脑的 IPv4 普通 HTTPS、TLS 1.2 / HTTP 1.1 复测和 IPv6 首页访问也取得过 HTTP 200，域名与证书校验通过。

**保留问题：当前电脑到 JP2 的直接 TCP 访问间歇超时。** 连续读取网站资源时，IPv4 和 IPv6 均出现过握手超时；IPv4 还出现过响应正文等待超时，不能把该电脑的整套网站资源检查判为全部通过。JP2 抓包可见 SYN 和服务器 TLS 数据段发生重传；同一服务在另一服务器的双栈资源比对正常，当前电脑的双栈 QUIC 代理请求也正常。现象更符合特定网络路径的 TCP 不稳定，但尚未定位具体设备、运营商或链路节点；不据此宣称确定根因或已修复网络问题，也未为此修改系统网络参数或降低 TLS 校验。

## 修复、复现与验收边界

真机首次启动时，原脚本在约 7 秒的证书签发完成前就运行状态检查，导致尚未就绪的网站显示异常。已增加安装、重装、重启后的 HTTPS 就绪等待：最多约 60 秒，使用实际配置端口和域名校验证书并等待 HTTP 200；服务停止或等待超时会提示，再由状态检查显示实际异常。新增 3 项回归检查覆盖证书暂未就绪后成功、持续 HTTP 错误超时及服务停止。修复后的重装、重启和删除后首次安装均已在 JP2 验证，最终安装第一次状态输出即正常。
